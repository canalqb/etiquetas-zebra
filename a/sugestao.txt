preciso criar um modo de importar
Bancos e arquivos suportados
Microsoft Excel — arquivos de planilha, como .xlsx.
Microsoft Access — bancos .accdb/Access.
Arquivos de texto — arquivos delimitados ou de texto, como .txt/CSV, dependendo da configuração do arquivo.
ODBC — permite conectar o ZebraDesigner a outros bancos de dados que tenham um driver ODBC disponível no Windows. 

ao fazer isso, ele cria um modal para exemplo
a origem tem 4 colunas, ele cria 4 campos de elementos em Listbox, para o usuário escolher qual campo irá representar a coluna da origem

Sim. A melhor forma é montar isso como um **importador genérico de fontes de dados**, em que o backend/API retorna as colunas encontradas e o JavaScript monta dinamicamente o modal.

 O fluxo pode ser:

 1. Usuário escolhe a origem:
   - Excel `.xlsx`
   - Access `.accdb`
   - CSV/TXT
   - ODBC
2. Faz upload ou informa a conexão.
3. AJAX envia a origem para o backend.
4. O backend retorna algo como:

   ```
   {
     "columns": ["Código", "Descrição", "Preço", "Quantidade"]
   }
   ```
5. O JS abre um modal.
6. Para cada coluna da origem, cria um `<select>`/Listbox.
7. O usuário escolhe qual **campo do sistema** representa aquela coluna.
8. Ao confirmar, o JS envia o mapeamento via AJAX.

 Por exemplo, se a origem tiver:

 | Coluna da origem | Campo do sistema |
| --- | --- |
| Código | `codigo` |
| Descrição | `descricao` |
| Preço | `preco` |
| Quantidade | `quantidade` |

o objeto enviado poderia ser:

```
{
  "codigo": "Código",
  "descricao": "Descrição",
  "preco": "Preço",
  "quantidade": "Quantidade"
}
```

let colunasOrigem = [];

function abrirModalMapeamento(colunas) {

    colunasOrigem = colunas;

    const container = document.getElementById("listaMapeamento");

    container.innerHTML = "";

    colunas.forEach((coluna, index) => {

        const row = document.createElement("div");

        row.className = "campo-mapeamento";

        const label = document.createElement("label");

        label.textContent = coluna;

        const select = document.createElement("select");

        select.dataset.coluna = coluna;

        const optionPadrao = document.createElement("option");

        optionPadrao.value = "";
        optionPadrao.textContent = "Não importar";

        select.appendChild(optionPadrao);

        camposSistema.forEach(campo => {

            const option = document.createElement("option");

            option.value = campo.value;
            option.textContent = campo.label;

            select.appendChild(option);
        });

        row.appendChild(label);
        row.appendChild(select);

        container.appendChild(row);
    });

    document
        .getElementById("modalImportacao")
        .classList.add("aberto");
}

function fecharModalMapeamento() {

    document
        .getElementById("modalImportacao")
        .classList.remove("aberto");
}

document
    .getElementById("btnFecharModal")
    .addEventListener("click", fecharModalMapeamento);

document
    .getElementById("btnCancelar")
    .addEventListener("click", fecharModalMapeamento);

document
    .getElementById("btnConfirmarImportacao")
    .addEventListener("click", function () {

        const selects = document.querySelectorAll(
            "#listaMapeamento select"
        );

        const mapeamento = {};

        selects.forEach(select => {

            const coluna = select.dataset.coluna;
            const campo = select.value;

            if (campo) {
                mapeamento[campo] = coluna;
            }
        });

        console.log(mapeamento);

        enviarMapeamento(mapeamento);
    });

function enviarMapeamento(mapeamento) {

    $.ajax({
        url: "/importacao/mapeamento",
        type: "POST",
        data: {
            mapeamento: JSON.stringify(mapeamento)
        },
        success: function (response) {

            console.log("Mapeamento salvo", response);

            fecharModalMapeamento();

        },
        error: function (xhr) {

            console.error(xhr);

            alert("Não foi possível salvar o mapeamento.");
        }
    });
}

 ## Um detalhe importante

 Eu faria uma pequena mudança na arquitetura: **não faria o JavaScript conhecer Excel, Access, CSV ou ODBC**.

 O JS deve receber apenas uma estrutura padronizada:

```
{
    "source": "excel",
    "table": "Produtos",
    "columns": [
        {
            "name": "CODIGO",
            "label": "CODIGO",
            "type": "string"
        },
        {
            "name": "DESCRICAO",
            "label": "DESCRICAO",
            "type": "string"
        },
        {
            "name": "PRECO",
            "label": "PRECO",
            "type": "decimal"
        },
        {
            "name": "ESTOQUE",
            "label": "ESTOQUE",
            "type": "integer"
        }
    ]
}
```

 Assim, tanto faz se o backend encontrou as colunas em Excel, Access, CSV ou ODBC. O frontend sempre trabalha com a mesma estrutura.

 Também dá para melhorar o modal para **tentar fazer o mapeamento automaticamente**. Por exemplo:

```
CODIGO       → Código
DESCRICAO    → Descrição
PRECO        → Preço
ESTOQUE      → Quantidade
```

 e deixar o usuário corrigir apenas o que não foi reconhecido.


Sim. Vou montar uma implementação completa, deixando o frontend **100% HTML + CSS \+ JavaScript/jQuery + AJAX**, e assumindo que você terá endpoints HTTP para o backend fazer a leitura de Excel/Access/CSV/ODBC.

 A arquitetura ficará assim:

```
[Selecionar origem]
       ↓
[Arquivo / conexão]
       ↓ AJAX
[Backend identifica colunas]
       ↓ JSON
[Modal de mapeamento]
       ↓
[Usuário ajusta os campos]
       ↓ AJAX
[Backend importa os registros]
```

 ## 3\. JavaScript

 Aqui está a parte principal do componente.

```
const Importador = {

    etapa: 1,

    tipoOrigem: null,

    dadosOrigem: null,

    camposSistema: [],

    init: function () {

        this.eventos();

        this.carregarCamposSistema();

    },

    eventos: function () {

        $("#btnAbrirImportacao").on(
            "click",
            () => this.abrir()
        );

        $("#btnFecharImportacao").on(
            "click",
            () => this.fechar()
        );

        $("#btnCancelarImportacao").on(
            "click",
            () => this.fechar()
        );

        $("#btnVoltarImportacao").on(
            "click",
            () => this.voltar()
        );

        $("#btnContinuarImportacao").on(
            "click",
            () => this.analisarOrigem()
        );

        $("#btnConfirmarImportacao").on(
            "click",
            () => this.confirmarImportacao()
        );

        $("input[name='tipoOrigem']").on(
            "change",
            function () {

                Importador.selecionarOrigem(
                    $(this).val()
                );

            }
        );

    },

    abrir: function () {

        this.etapa = 1;

        this.tipoOrigem = null;

        this.dadosOrigem = null;

        $("#modalImportacao").addClass("aberto");

        this.mostrarEtapa(1);

        $("input[name='tipoOrigem']")
            .prop("checked", false);

        $("#arquivoImportacao").val("");

    },

    fechar: function () {

        $("#modalImportacao")
            .removeClass("aberto");

    },

    selecionarOrigem: function (tipo) {

        this.tipoOrigem = tipo;

        $(".area-origem").hide();

        if (tipo === "excel") {

            $("#areaArquivo").show();

            $("#arquivoImportacao")
                .attr("accept", ".xlsx,.xls");

        }

        else if (tipo === "access") {

            $("#areaArquivo").show();

            $("#arquivoImportacao")
                .attr("accept", ".accdb,.mdb");

        }

        else if (tipo === "csv") {

            $("#areaArquivo").show();

            $("#arquivoImportacao")
                .attr("accept", ".csv,.txt");

        }

        else if (tipo === "odbc") {

            $("#areaOdbc").show();

            this.carregarDsn();

        }

    },

    carregarCamposSistema: function () {

        $.ajax({

            url: "/api/importacao/campos",

            type: "GET",

            dataType: "json",

            success: function (response) {

                Importador.camposSistema =
                    response.campos || [];

            },

            error: function () {

                Importador.camposSistema = [

                    {
                        value: "codigo",
                        label: "Código"
                    },

                    {
                        value: "descricao",
                        label: "Descrição"
                    },

                    {
                        value: "preco",
                        label: "Preço"
                    },

                    {
                        value: "quantidade",
                        label: "Quantidade"
                    }

                ];

            }

        });

    },

    carregarDsn: function () {

        $.ajax({

            url: "/api/importacao/odbc/dsns",

            type: "GET",

            dataType: "json",

            success: function (response) {

                const select = $("#dsnOdbc");

                select.empty();

                select.append(
                    '<option value="">Selecione uma conexão</option>'
                );

                response.dsns.forEach(function (dsn) {

                    select.append(
                        $("<option>", {
                            value: dsn.value,
                            text: dsn.label
                        })
                    );

                });

            }

        });

    },

    analisarOrigem: function () {

        this.limparMensagem();

        if (!this.tipoOrigem) {

            this.mensagem(
                "Selecione uma origem.",
                "erro"
            );

            return;
        }

        if (
            this.tipoOrigem === "excel" ||
            this.tipoOrigem === "access" ||
            this.tipoOrigem === "csv"
        ) {

            const arquivo =
                $("#arquivoImportacao")[0].files[0];

            if (!arquivo) {

                this.mensagem(
                    "Selecione um arquivo.",
                    "erro"
                );

                return;
            }

            this.analisarArquivo(arquivo);

            return;
        }

        if (this.tipoOrigem === "odbc") {

            this.analisarOdbc();

        }

    },

    analisarArquivo: function (arquivo) {

        const formData = new FormData();

        formData.append(
            "arquivo",
            arquivo
        );

        formData.append(
            "tipo",
            this.tipoOrigem
        );

        this.loading(
            true,
            "Analisando arquivo..."
        );

    montarMapeamento: function () {

                    : coluna.name;

                    ? ""
                    : coluna.type || "";

            );

            row.append(select);

            container.append(row);

        });

    buscarMapeamentoAutomatico: function (coluna) {

        const normalizado =
            this.normalizar(coluna);

        for (
            let campo of this.camposSistema
        ) {

            const nomeCampo =
                this.normalizar(campo.value);

            const labelCampo =
                this.normalizar(campo.label);

            if (
                normalizado === nomeCampo ||
                normalizado === labelCampo
            ) {

                return campo;

            }

        }

        const aliases = {

            codigo: [
                "cod",
                "codigo",
                "id",
                "codigoproduto"
            ],

            descricao: [
                "descricao",
                "descrição",
                "nome",
                "produto"
            ],

            preco: [
                "preco",
                "preço",
                "valor",
                "valorunitario"
            ],

            quantidade: [
                "quantidade",
                "qtd",
                "estoque",
                "qtde"
            ]

        };

        for (
            let campo of this.camposSistema
        ) {

            const alias =
                aliases[campo.value];

            if (!alias) {
                continue;
            }

            if (
                alias.includes(normalizado)
            ) {

                return campo;

            }

        }

        return null;

    },

    normalizar: function (valor) {

        return String(valor)
            .normalize("NFD")
            .replace(/[\u0300-\u036f]/g, "")
            .toLowerCase()
            .replace(/[^a-z0-9]/g, "");

    },

    confirmarImportacao: function () {

        const mapeamento = {};

        let possuiCampo = false;

        $("#listaMapeamento select")
            .each(function () {

                const coluna =
                    $(this).data("coluna");

                const campo =
                    $(this).val();

                if (campo) {

                    possuiCampo = true;

                    mapeamento[campo] =
                        coluna;

                }

            });

        if (!possuiCampo) {

            this.mensagem(
                "Selecione pelo menos um campo.",
                "erro"
            );

            return;

        }

        const dados = {

            tipo: this.tipoOrigem,

            origem: this.dadosOrigem.origem || null,

            tabela: this.dadosOrigem.tabela || null,

            mapeamento: mapeamento

        };

        this.loading(
            true,
            "Importando dados..."
        );

        $.ajax({

            url: "/api/importacao/importar",

            type: "POST",

            contentType:
                "application/json",

            data:
                JSON.stringify(dados),

            dataType: "json",

            success: (response) => {

                this.loading(false);

                if (!response.sucesso) {

                    this.mensagem(
                        response.mensagem ||
                        "Não foi possível importar.",
                        "erro"
                    );

                    return;
                }

                this.mensagem(
                    response.mensagem ||
                    "Importação concluída.",
                    "sucesso"
                );

                setTimeout(
                    () => this.fechar(),
                    1200
                );

            },

            error: (xhr) => {

                this.loading(false);

                this.mensagem(
                    this.obterErro(xhr),
                    "erro"
                );

            }

        });

    },

    mostrarEtapa: function (etapa) {

        this.etapa = etapa;

        if (etapa === 1) {

            $("#etapaOrigem").show();

            $("#etapaMapeamento").hide();

            $("#btnVoltarImportacao").hide();

            $("#btnContinuarImportacao").show();

            $("#btnConfirmarImportacao").hide();

        }

        if (etapa === 2) {

            $("#etapaOrigem").hide();

            $("#etapaMapeamento").show();

            $("#btnVoltarImportacao").show();

            $("#btnContinuarImportacao").hide();

            $("#btnConfirmarImportacao").show();

            $("#etapaImportacao").text("2 de 2");

        }

    },

    voltar: function () {

        this.mostrarEtapa(1);

    },

    loading: function (mostrar, texto) {

        if (mostrar) {

            $("#textoLoading").text(texto);

            $("#loadingImportacao").show();

        }
        else {

            $("#loadingImportacao").hide();

        }

    },

    mensagem: function (

        tipo
    ) {

        const elemento =
            $("#mensagemImportacao");

        elemento
            .removeClass("erro sucesso")
            .addClass(tipo)
            .text(texto)
            .show();

    },

    limparMensagem: function () {

        $("#mensagemImportacao")
            .hide()
            .removeClass("erro sucesso")
            .text("");

    },

    obterErro: function (xhr) {

        if (
            xhr.responseJSON &&
            xhr.responseJSON.mensagem
        ) {

            return xhr.responseJSON.mensagem;

        }

        return "Ocorreu um erro ao processar a importação.";

    }

};

$(document).ready(function () {

 Quando o usuário clicar em **Importar**, o AJAX enviará:

```
{
    "tipo": "excel",

        "codigo": "CODIGO",
        "descricao": "DESCRICAO",
        "preco": "PRECO",
        "quantidade": "ESTOQUE"

```

 Isso é interessante porque o backend não precisa adivinhar mais nada.

 Ele recebe explicitamente:

```
campo do sistema → coluna da origem

 Por exemplo:

```
codigo      → CODIGO
descricao   → DESCRICAO
preco       → PRECO

```

### 2.4 JS — injeção de `^PQ` (reaproveitando o padrão da linha 5422)

Ponto crítico que a auditoria encontrou: **o lote pode já ter `^PQ` embutido** (caminho de serialização nativa `^SN+^PQ`, linha 5419-5432). Se a função de cópias simplesmente adicionar outro `^PQ`, o ZPL fica com dois comandos de quantidade no mesmo bloco — a impressora normalmente obedece só o último, então o valor da serialização nativa (que representa "1 cópia por número de série") seria silenciosamente substituído pela quantidade de cópias, quebrando a lógica da série. A função abaixo trata os dois casos:

```js
/**
 * Injeta ^PQ em cada bloco ^XA...^XZ de um ZPL (single ou lote).
 * Se o bloco já tiver ^PQ (serialização nativa), MULTIPLICA em vez de substituir,
 * assim "3 cópias" sobre um lote de 10 séries via ^SN+^PQ vira ^PQ30 corretamente.
 */
function injetarQuantidadeZPL(zpl, qtd) {
  qtd = Math.max(1, parseInt(qtd, 10) || 1);
  if (qtd === 1) return zpl; // nada a fazer, evita reprocessar à toa

  var blocos = zpl.split(/(?=\^XA)/).filter(function (b) { return b.trim().length; });
  var resultado = blocos.map(function (bloco) {
    var m = /\^PQ(\d+)/.exec(bloco);
    if (m) {
      var atual = parseInt(m[1], 10) || 1;
      return bloco.replace(/\^PQ\d+/, "^PQ" + (atual * qtd));
    }
    return bloco.replace(/\^XZ\s*$/, "^PQ" + qtd + "\n^XZ");
  });
  return resultado.join("\n\n");
}
```

## 4. Sistema de ícones — diretrizes (a parte "me dê mais ideias")

### 4.1 Duas bibliotecas de ícones convivendo hoje
O projeto usa **Font Awesome** (`fas`/`far`) na maioria dos botões e **Bootstrap Icons** (`bi-*`) em alguns pontos específicos: tema (`bi-moon-stars`/`bi-sun`), espelho (`bi-flip-horizontal`), reverso (`bi-circle-half`), preview (`bi-eye`), imagem (`bi-image`), além de vários ícones dentro dos modais (`bi-folder-check`, `bi-collection`, `bi-diagram-3`, `bi-box-seam`...). Isso não é um erro — os dois conjuntos já estão carregados (Bootstrap 5 traz Bootstrap Icons de brinde) — mas vale uma regra explícita: **Font Awesome para ações da paleta/ribbon** (ferramentas, elementos, comandos), **Bootstrap Icons para navegação/estado de UI** (abas, modais, indicadores). Hoje já é quase isso na prática; só falta documentar para não virar escolha aleatória em cada novo botão.

### 4.2 Estados visuais que faltam formalizar
Os toggles (`btn-tema`, `btn-toggle-espelho`, `btn-toggle-reverso`, `btn-toggle-imgprint`) já trocam de cor (`icon-btn-success` ↔ `icon-btn-muted`) e opacidade quando ativos — isso está certo visualmente. O que falta: **nenhum deles tem `aria-pressed`**. Para leitor de tela, um botão que liga/desliga precisa de `aria-pressed="true/false"` sincronizado com o estado — hoje a mudança é só cor, invisível para quem não enxerga. Ajuste pequeno e mecânico: adicionar `btn.setAttribute("aria-pressed", ativo)` em cada função `atualizar()` que já existe (`ligarToggleFlag`, `atualizarBtnImgPrint`, `aplicarTema`).

### 4.3 Indicador de conexão com a impressora
Você tem 3 caminhos de envio (`cloud`, `http`, `ftp`/`tcp` via `print-server.js` local). Hoje o único feedback é o `notify()` toast depois de tentar imprimir — o usuário só descobre que o `print-server.js` não está rodando (`node print-server.js`) no momento em que clica em Imprimir. Um ícone fixo de status (verde/cinza/vermelho, tipo `fa-circle` pequeno ao lado do IP configurado) que faz um `fetch` leve em `http://localhost:3001/` (a rota `GET /` já existe no seu `print-server.js`, retorna `{ok:true, servico:...}`) resolveria isso — dá para saber antes de imprimir se o servidor local está de pé, sem esperar a etiqueta falhar.

### 4.4 Feedback de "^PQ nativo" vs. "N blocos"
Quando o lote usa a otimização de serialização nativa (`^SN`+`^PQ`, 1 bloco só), isso hoje só aparece num texto do `notify()`. Um badge pequeno no modal de lote/impressão ("⚡ Modo otimizado: 1 bloco enviado para N etiquetas") reforça visualmente que o sistema escolheu o caminho mais rápido — útil também como diagnóstico quando o usuário perceber que o envio de um lote de 500 unidades foi "instantâneo" e quiser entender por quê.

### 4.5 Ícone dedicado para fila/progresso de impressão em lote
Hoje o envio do lote é um `fetch()` único com o ZPL inteiro concatenado — o usuário não vê progresso, só o toast final de sucesso/erro. Se algum dia isso migrar para envio em partes (por exemplo, para impressoras/lotes muito grandes onde um único payload trava a conexão FTP), vale reservar desde já um espaço visual (a própria barra de status do §3 pode virar uma barra de progresso: "Enviando etiqueta 12 de 42...").

### 4.6 Ícones para o driver de impressão (`print-server.js`)
Como o `print-server.js` já expõe dois protocolos (`ftp` e `tcp`, porta configurável via `FTP_PORT`/`TCP_PORT`), o seletor de protocolo na UI merece um ícone por protocolo em vez de só texto — `fa-server` para FTP, `fa-bolt` para TCP Direct (9100, mais rápido/sem handshake) — ajuda o usuário leigo a escolher sem entender de portas.

### 4.7 Auto-hospedar o Font Awesome em vez de CDN
Ambiente de chão de fábrica/depósito às vezes não tem internet estável — se o Font Awesome via `cdnjs` cair, todos os ícones da ribbon desaparecem de uma vez (viram quadrados vazios). Vale considerar baixar o subconjunto de ícones realmente usado (são ~35 ícones únicos no arquivo todo) e servir localmente junto do `index.html`, eliminando essa dependência externa — principalmente porque o `print-server.js` já assume uso 100% local (`127.0.0.1`).

### 4.8 Paleta de ícones testada para daltonismo
A distinção "Escala de Cinza" (`fa-fill-drip`, laranja/cinza) vs. "Preto e Branco" (`fa-adjust`, escuro) depende de forma do ícone, não só de cor — isso já está correto (bom sinal). Mantenha esse princípio ao criar novos ícones de modo/qualidade: nunca diferenciar dois estados **só** pela cor do `icon-btn-*`, sempre trocar também o ícone Font Awesome.

## 1. Diagnóstico

**Sintoma relatado:** duplo clique num elemento de texto (ex.: Subtítulo) não abre edição no local — comportamento esperado em apps de design (Canva/Figma).

**Causa raiz:** não existe nenhum listener de `dblclick` no `index.html`. O único caminho de edição de texto hoje é: **clique direito** no elemento → abre `#modal-editor` (o `contextmenu` listener move `#form-inspector` para dentro do modal) → usuário localiza o campo `#insp-texto` no formulário → digita → fecha o modal.

Isso já estava documentado como limitação conhecida no seu próprio `pedidos_e_solucoes.md`, Pedido 1.14 (Editor de formas geométricas): *"sem edição por duplo clique no canvas (infraestrutura inexistente — pulado conforme plano)"*. Ou seja, não é regressão — é um recurso que nunca chegou a ser construído.

**Modelo de renderização confirmado (necessário para o patch funcionar sem quebrar nada):**
- Cada elemento no canvas é um `<div class="canvas-el" data-id="...">` posicionado em `absolute`, criado dentro do `elements.forEach(...)` de `renderStudio()`.
- Para `texto`/`sub`/`nome`/`serie`, o texto vive num `<span>` filho (`textSpan.textContent = el.texto`).
- Para formas com texto (`borda`/`elipse`/`raio`, do Pedido 1.14), o texto vive num `<div class="forma-texto">` filho, e só é criado quando `el.texto` já não é vazio — a função `ehFormaComTexto(el.tipo)` (já existe no código) identifica esses tipos.
- Seleção e arraste usam `mousedown` no próprio `div` (não `click`) — isso importa porque qualquer solução de edição precisa impedir que um clique **dentro** do campo de edição dispare o arraste do elemento pai.
- Clique direito (`contextmenu`) no `div` já está implementado e não pode ser quebrado pela nova função.

---

## 2. Especificação da solução

Duplo clique no elemento sobrepõe um campo de edição (`<input>` para texto de uma linha, `<textarea>` para elementos multilinha ou formas com texto) exatamente por cima do `div`, pré-preenchido com o texto atual e já selecionado. **Enter** confirma (ou **Ctrl+Enter** em campo multilinha), **Esc** cancela, perder o foco (`blur`) confirma.

Escopo: `texto`, `sub`, `nome`, `serie` e qualquer tipo em que `ehFormaComTexto(tipo)` seja verdadeiro (`borda`, `elipse`, `raio`) — inclusive quando a forma ainda não tem texto nenhum, permitindo adicionar texto pela primeira vez via duplo clique, não só editar o existente.

**Ponto técnico que exige atenção na implementação:** um clique dentro do campo sobreposto (para posicionar cursor ou selecionar parte do texto) borbulha (`bubbles`) até o `mousedown` do `div` pai, que hoje inicia arraste/redimensionamento. A solução é chamar `e.stopPropagation()` nos eventos `mousedown`, `click`, `dblclick` e `contextmenu` **do próprio campo de edição** — não é necessário alterar o listener de arraste já existente no `div`, o que reduz o risco de regressão a zero nesse ponto.

## 4. Casos de borda cobertos pelo patch

| Caso | Comportamento |
|---|---|
| Elemento sem texto ainda (forma recém-criada) | Duplo clique abre campo vazio — permite digitar texto pela primeira vez |
| Elemento multilinha (`el.multiline`) | Usa `<textarea>`; Enter quebra linha, Ctrl+Enter confirma |
| Forma com texto (borda/elipse/raio) | Usa `<textarea>` (mesma lógica do `^FB`/word-wrap) e a cor de contraste de `getCorTextoElemento()` |
| Clicar dentro do campo para mover o cursor | Não dispara arraste do elemento pai (`stopPropagation` no `mousedown` do campo) |
| Clique direito acidental durante a edição | Não reabre o modal antigo (`stopPropagation` no `contextmenu` do campo) |
| Segundo duplo clique enquanto já em edição | Ignorado (`if (div.querySelector(".edicao-inline-input")) return;`) |
| Perder o foco sem confirmar explicitamente | `blur` chama `confirmar()` — nunca perde a edição por engano |
| Digitar e não mudar nada | `confirmar()` só re-renderiza ZPL se `novoTexto !== el.texto` — evita `renderStudio()`/`renderZPL()` desnecessário |
